# PHPDoc・JSDocのコメント規約

PHPはPHPDoc、JavaScriptはJSDocを使用する。関数/メソッドの目的と全引数・戻り値の型、意味、書式、単位、許容範囲を記載する。単位がない値へ架空の単位は付けない。

- PHPは `@param 型 $引数名 説明`、`@return 型 説明` を使う。既存の型宣言も維持する。
- JavaScriptは `@param {型} 引数名 説明`、`@returns {型} 説明` を使う。
- 省略可能な引数は既定値と省略時の動作を記載する。引数なしなら@paramは作らない。
- 戻り値なしはvoid、非同期処理はPromiseと解決値を説明する。
- 配列/オブジェクトは要素やプロパティの意味を説明する。JSの共有構造には必要に応じて@typedef/@propertyを使う。
- 実際に投げる例外は@throwsへ型と条件を記載する。検証していない入力や安全性を保証しない。
- 学習のため主要処理の理由を短い行内コメントで補足する。全行の逐語説明や一括改名は行わない。
- Bladeの表示説明はBladeコメントを使い、埋込PHP/JSの関数はそれぞれの形式に従う。
- ライセンス/既存の有用な説明を保持し、依存物/生成物は編集せず元ソースを修正する。
- コメント追加後も構文、処理の差分、既存テスト、必要なビルドと画面操作を確認する。
- 個人環境、認証情報、内部文書へのリンクを追加しない。

ドキュメント生成を想定した形式。生成ツールの導入/出力検証は別に実施する。Google独自規約への準拠は主張しない。
